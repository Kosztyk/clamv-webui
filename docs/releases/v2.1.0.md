# ClamAV Web UI v2.1.0

- GitHub publication date **22 November 2026**
- Git tag `v2.1.0`
- Docker Hub image `kosztyk/clamav-web-client:v2.1.0`

## Highlights

- Resolves the open audit backlog tracked in issues **#25–#57**: validation, audit safety, performance, privacy, database indexes/migrations, CI, release engineering, API contracts and upgrade testing.
- Upgrades native ClamAV runtime libraries and the default ClamD service to **1.4.7**, fixing the November 2026 ClamAV security CVEs reported against 1.4.6.
- Adds PostgreSQL first-start compatibility repair for the legacy `idx_processed_path` UNIQUE-constraint form before Flyway V9.
- Makes trusted **Direct HTTP** session-cookie mode a persistent Configuration Center choice for installations that intentionally run without a reverse proxy.
- Enforces `libfontenc>=1.1.10-r0`; documents Alpine 3.24's `musl 1.2.6-r3` backport with digest-scoped OpenVEX for `CVE-2026-107891`.
- Adds a single required CI `gate`, database upgrade tests, API contract checks, and Java and Go quality/security checks. The source includes a tag-triggered workflow to sign and verify release images and CLI artifacts.

## Docker Scout / VEX

The Docker Hub release can carry the OpenVEX assessment using:

```bash
bash scripts/attach-release-vex.sh docker.io/kosztyk/clamav-web-client:v2.1.0 2.1.0
```

Publisher-trusted verification:

```bash
docker scout cves \
  --org kosztyk \
  --vex-author 'https://github.com/Kosztyk/clamv-webui' \
  --only-vex-affected \
  registry://docker.io/kosztyk/clamav-web-client:v2.1.0
```

A VEX-aware scan should report **0C / 0H / 0M / 0L** for the verified release image. Docker Hub's ordinary layer vulnerability view may still list the raw musl advisory even when Scout has consumed the VEX attestation.

## Upgrade

1. Back up the database plus mounted `conf/` and `data/`.
2. Deploy the `v2.1.0` image/source without manually altering Flyway history.
3. PostgreSQL legacy constraint repair runs automatically before Flyway when needed.
4. Direct-HTTP users should save **Direct HTTP configuration** in `/setup/`, restart, then clear stale browser cookies and sign in again. HTTPS users should keep Secure cookies enabled.
5. Validate login, EICAR scanning, ClamdTop/health, configured endpoints, quarantine, and any external identity/provider integration used in production.
