# ClamAV Web UI v2.1beta1 — beta release notes

> Pre-release candidate. Do not use in production until the beta source import, CI and live Docker scanning tests pass. This beta branch is deliberately separate from `main`.

## New safe scanning defaults
- New installs use INSTREAM upload scanning (native pathname scanning OFF, fallback ON). This works without giving a remote or separate `clamd` access to private uploaded files.
- Optional native `clamdtop` filenames: use `Dockerfile.clamd-uid` plus `docker-compose.native-path.yml`. The scanner runs under numeric UID 10001, mounts **only** `data/uploads` read-only, and must pass the runtime verification before enabling native path scans in Configuration Center.
- Automatic cleanup remains: successful clean uploads are deleted, and infected uploads are deleted when quarantine is off; leftovers are eligible for 24-hour retention cleanup. Uploaded directories/files stay at `0700`/`0600`. Confirm deletion using clean/EICAR smoke tests.
- PATH/WATCH scanning still requires accessible scan roots; INSTREAM upload mode does not make arbitrary remote paths available to clamd.

## Retained fixes from issues #13–#24
- #13 trusted forwarded headers and HTTPS recognition; #14 Basic/form-login lockout; #15 clamd network/data isolation; #16 LDAP/OIDC secret destination binding; #17 reliable watcher traversal and retry; #18 upload cleanup and private modes; #19 bounded upload filenames and DB transactions; #20 daemon timeouts and scheduler concurrency; #21 token path scopes; #22 session revocation; #23 bounded throttling; #24 path existence privacy.
- Login error pages remain accessible anonymously without weakening CSRF or protected routes.
- Existing database contents, credentials and application role mappings are not intentionally reset.

## Installation and migration
See [beta deployment examples](../BETA_DEPLOYMENT_EXAMPLES.md), [production scanning](../PRODUCTION_SCANNING.md) (after the full source import), and [complete user guide](../COMPLETE_USER_GUIDE.md).
Back up the DB, `conf/` and `data/`. Do not overwrite your production Compose with an example. Existing Configuration Center settings override new defaults, while Docker environment overrides take precedence over GUI settings. Do not copy another system's Docker gateway CIDR; determine the actual trusted proxy peer. Legacy Flyway baselining is an opt-in procedure for the appropriate existing database, not a setting for every install.

## Beta acceptance gates
Run `mvn -B verify`, the source/secrets check, clean and EICAR upload tests, delete/retention tests, local and LDAP login tests, HTTPS reverse-proxy tests, and verify scanner isolation. The optional native scanner deployment requires additional real Docker validation. The tagged prerelease workflow only publishes after verification passes.
