Authentication Management

Manage sign-in providers and recovery access.

Manage local access and external identity providers. UI settings take precedence over Docker bootstrap settings. New sign-ins use saved settings immediately.

Local / Recovery

Local Authentication & Break-glass Access

Always enabled. Local login remains independent when LDAP or OIDC is unavailable. Unrestricted self-registration is disabled.

Maintain at least one enabled local administrator with a unique password of at least 12 characters. Manage local users and rotate passwords under Admin → Users.

Local login cannot be disabled here. External users receive no roles unless an exact group is explicitly mapped.

LDAP / Active Directory

LDAPS or StartTLS required; Java must trust the server certificate. Test binds before enabling LDAP. Testing does not save the form; use Save LDAP settings to persist it.

OIDC / Single Sign-On

Authentik / Keycloak / standards-based issuer. HTTPS is required. Testing does not save the form; use Save OIDC settings to persist it. The authorization-code flow still verifies state and nonce.

Separate scopes with commas or spaces. Include openid; request groups only if your provider supports it.

OAuth callback: /login/oauth2/code/clamav on your trusted HTTPS public hostname. The redirect URI must match your IdP client configuration.

Test performs HTTPS issuer discovery; a real SSO login verifies the client secret. Unmapped users have no access.

For production, submit new credentials over HTTPS, protect conf/auth-settings.key, and retain a known-good local administrator.
